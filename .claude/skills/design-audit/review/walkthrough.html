Treq design system

The treq-ui styleguide (gpui-styleguidist), with every snapshot CI checks, and how each component answers Krug's questions in Don't Make Me Think.

The six principles

  • Self-evident A first-time user can tell what it is and what it does without thinking.
  • Conventions It works the way macOS, Windows and GitHub already taught them.
  • Clear hierarchy The most important thing is the most prominent thing.
  • Obvious clickability What can be clicked looks clickable, and what can't, doesn't.
  • Less noise Each signal means one thing, so the important ones stand out.
  • What just happened Waiting, emptiness and results are always explained.

How it's held in place

  • Styleguide. cargo run -p treq-ui --example styleguide. The snapshots below are the committed baselines, and CI fails when a render drifts.
  • Lints. Six ast-grep rules block raw colours, raw text sizes, zpx spacing, hand-rolled Esc handling, ad-hoc controls and Yes/No copy.
  • Audit. /design-audit compares screenshots and code for drift.
  • Compound examples. These are built only from other ui parts, so they inherit each part's rules.
