# Best Graphite Alternatives for Stacked PRs

_Graphite made stacked pull requests mainstream. You can now get stacks from GitHub itself, from open source CLIs, or from a desktop app._

[Stacked PRs](/learn/concepts/git/stacked-prs) split one large change into a chain of small, dependent pull requests. Graphite is the best-known product for them. Teams look for an alternative when they want open source, no per-seat bill, or a workflow that fits coding agents. Facts were checked against each project's own site or repository in November 2026.

## The Alternatives

| Tool | Form | License | Where stacks live |
| --- | --- | --- | --- |
| Treq | Desktop app | Apache 2.0 | Local agent workspaces, then GitHub PRs |
| GitHub stacked PRs | Built into GitHub, `gh stack` CLI | Proprietary service | GitHub |
| GitButler | Desktop app, CLI and TUI | FSL-1.1-MIT | Local branches, then GitHub PRs |
| ghstack | CLI | Open source | One PR per commit on GitHub |
| spr | CLI | Open source | One PR per commit on GitHub |
| git-town | CLI | Open source | Branches on any Git host |
| Jujutsu | Version control system | Apache 2.0 | Local commits, pushed as branches |
| Sapling | Version control system | Open source | Local commits, reviewed in ReviewStack |

## 1. Treq

[Treq](/) stacks local workspaces before any pull request exists. Each coding agent works in its own layer. When a lower layer changes, Treq rebases the layers above it and sends conflicts back to the agent. You review each layer locally, then open ordinary stacked PRs on GitHub. The desktop app is free and open source. See [Treq as a Graphite Alternative](/learn/graphite-alternative) and [Treq vs Graphite](./treq-vs-graphite-for-ai-teams).

## 2. GitHub Stacked PRs

GitHub added native stacked pull requests, in public preview since July 2026. Each PR targets the branch of the PR below it, and GitHub retargets the stack when a lower PR merges. The `gh stack` extension manages stacks from the terminal. It is the default choice if you want stacks without another tool.

## 3. GitButler

GitButler is a Git client with stacked and parallel branches in one working directory. It ships a desktop app, a CLI and a TUI, and opens GitHub's native stacked PRs. Its license is the Functional Source License, which converts to MIT after two years. It is fair source, not an OSI-approved open source license.

## 4. ghstack and spr

ghstack and spr both turn each local commit into its own pull request. You keep a linear branch of commits locally, and the tool creates and updates one PR per commit. They suit developers who already think in commits, not branches.

## 5. git-town

git-town adds commands for creating, syncing and shipping stacked branches. It works with GitHub, GitLab, Bitbucket and other hosts because it only uses plain Git branches.

## 6. Jujutsu

[Jujutsu](/learn/concepts/git/version-control) is a Git-compatible version control system that rebases descendant commits automatically when you edit an earlier one. That makes stacks cheap to maintain by hand. Treq uses Jujutsu internally for the same reason, so you get its rebasing without learning `jj`.

## 7. Sapling

Sapling is Meta's source control system, built around stacks of commits. ReviewStack provides a stack-aware review interface for GitHub pull requests.

## How to Choose

- **No new tools:** GitHub stacked PRs.
- **Coding agents write most of your changes:** Treq, because stacking happens where the agents work.
- **A desktop Git client with stacks:** GitButler.
- **One PR per commit from the terminal:** ghstack or spr.
- **Any Git host:** git-town.
